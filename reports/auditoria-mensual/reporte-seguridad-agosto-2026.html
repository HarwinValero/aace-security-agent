9. Hallazgos Críticos

🔴
F-001 · Sin WAF activo — alcaldia-cali-portal
La cuenta alcaldia-cali-portal no tiene ningún WebACL WAF configurado. Los recursos web están expuestos a ataques de Capa 7: SQL Injection, XSS, DDoS, bots automatizados y exploits de vulnerabilidades conocidas sin ningún filtro perimetral.
Control: CIS 2.4 · SEC-WAF-001 · SOC2 CC7.1  |  SLA: 24 horas  |  Acción: Crear WebACL con Core Rule Set + Known Bad Inputs + SQL DB
🔴
F-002 · GuardDuty deshabilitado — alcaldia-cali-portal
Sin GuardDuty activo, no existe detección automática de amenazas. Actividades maliciosas como accesos no autorizados, uso anómalo de credenciales, instancias comprometidas para minería de criptomonedas o exfiltración de datos pasarían completamente inadvertidas.
Control: SEC-LOG-003 · SOC2 CC7.1  |  SLA: 24 horas  |  Acción: Habilitar GuardDuty + configurar delegated admin
🔴
F-003 · Security Hub deshabilitado — alcaldia-cali-portal
Sin Security Hub no hay visibilidad centralizada de la postura de seguridad, ni correlación de hallazgos de GuardDuty, Inspector, Macie y Config. Imposible mantener compliance continuo ni generar scorecards automáticos.
Control: SEC-LOG-004 · SOC2 CC7.2  |  SLA: 24 horas  |  Acción: Habilitar Security Hub + estándares CIS + AWS Foundational
🔴
F-004 · AWS Config deshabilitado — alcaldia-cali-portal
Sin AWS Config no existe inventario continuo de recursos ni evaluación automática de compliance rules. Cambios de configuración riesgosos (apertura de Security Groups, eliminación de cifrado, etc.) no se detectan ni alertan.
Control: SOC2 CC7.2 · CIS  |  SLA: 24 horas  |  Acción: Habilitar AWS Config + Config Rules básicas
🔴
F-005 · 46 Buckets S3 sin Block Public Access confirmado — alcaldia-cali-workload
46 buckets reportados como "Unprotected". Entre ellos se encuentran buckets de alta sensibilidad: estado Terraform (infraestructura completa), logs CloudTrail, backups SAP, documentos Orfeo, y datos de Secretaría de Turismo. Una exposición pública de estos datos representaría un incidente de seguridad mayor.
Control: CIS 3.1 · SEC-S3-001  |  SLA: 24 horas  |  Acción: aws s3api put-public-access-block en todos los buckets sensibles
⚠️
F-006 · 2 Security Groups con 0.0.0.0/0 — alcaldia-cali-workload
Dos Security Groups tienen reglas de entrada con origen abierto al mundo. Si estas reglas incluyen puertos SSH (22), RDP (3389), o bases de datos (3306/5432), representan un vector de ataque directo sobre 82 instancias EC2.
Control: CIS 5.1 · SEC-NET-001  |  SLA: 7 días  |  Acción: Auditar y restringir reglas a rangos IP corporativos
⚠️
F-007 · WAF Logging deshabilitado — alcaldia-cali-workload
El WebACL CloudFront activo no tiene logging habilitado. Se pierden las trazas de ataques bloqueados, patrones de tráfico malicioso e intentos de explotación, lo que impide el análisis forense post-incidente y el ajuste fino de las reglas WAF.
Control: SEC-WAF-001  |  SLA: 7 días  |  Acción: Habilitar WAF logging hacia S3 o CloudWatch Logs
